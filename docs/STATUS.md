**How to use this file** (full rules in [00-overview.md](00-overview.md) §8)

- Edit **only your own rows** and the Requests table. Never rewrite another agent's row.
- Status values: `todo` · `blocked` (put the reason in Notes) · `in-progress` · `in-review` (PR open) · `done` (merged into `integration/blog-contact`) · `dropped`.
- A task may start only when every ID in *Depends on* is `done` (or the dependency is marked **soft**: you may start in parallel but cannot finish before it).
- Branches: **one per agent** — `feat/design`, `feat/frontend`, `feat/integrations`, `feat/qa` — cut from `integration/blog-contact`; one commit (or small series) per task ID, task ID in the commit message; PR back into `integration/blog-contact`. Parallel agents must use separate git worktrees. **Nothing merges to `master` except M-1.** `master` deploys.
- Base branch `integration/blog-contact` is created by the owner/Tech Lead from `master` **after** `git pull` (O-0).
